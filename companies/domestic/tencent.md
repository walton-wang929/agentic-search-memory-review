# 腾讯：微信搜一搜 / 元宝

## 产品机制

### 公开可见

- 元宝提供联网搜索、文档与图片理解、多轮对话，并接入微信搜一搜、公众号/视频号内容等腾讯生态信息源。
- 元宝已进入微信入口，并逐步连接评论区、微信小店等搜索与交易服务。
- 在微信中，用户可主动把文章、文件或聊天内容发给元宝处理；这种「用户选择上下文」是强 consent 的短/中期 memory 输入。

### 未充分公开

- 元宝是否具备类似 Saved Memories 的长期用户记忆管理页，以及不同版本/入口的覆盖范围。
- 元宝能否默认读取私人微信聊天、联系人或全量收藏；没有官方证据时不应假设可以。
- 微信搜一搜的搜索/内容画像如何进入元宝 Agent。
- 微信官方说明 AI 搜索不使用朋友圈和个人聊天等私密内容；普通搜一搜的个性化搜索结果可单独关闭。

## Memory 分层映射

| 层级 | 可能机制 | 证据等级 |
|---|---|---|
| 短期 | 当前对话与主动转发内容 | 产品可见 |
| 中期 | 元宝历史会话、文档任务、微信中主动提供的内容 | 部分可见 |
| 长期 | 腾讯内容兴趣图谱、账户偏好 | 平台能力存在；Agent 使用方式未知 |

## Agentic Search 注入点

- **Retrieval**：公众号、视频号、搜一搜和全网内容。
- **Context**：用户主动转发的文章、文件或消息。
- **Action**：微信小店、小程序、服务和支付是闭环优势。
- **Proactive**：服务通知和公众号订阅基础设施适合中期任务，但需要明确授权。

## 技术实现判断

- 微信生态更适合「按需授权读取」而非默认汇总私人数据。
- 元宝应把个人微信内容、公开内容兴趣和 Agent 自身历史严格分 scope。
- 小程序与交易工具调用需要独立权限、确认和审计。
- 腾讯云 Agent Memory 已公开原始对话、原子记忆、场景记忆、核心记忆的分层架构，并支持关键词 + 向量 + RRF 检索、来源下钻、订正与删除；这证明技术底座存在，但不能直接等同于元宝消费端已使用。

## 优势

- 搜索、内容、社交、服务、小程序与支付闭环完整。
- 公众号和私域知识具有通用 Web 无法覆盖的内容。

## 风险与开放问题

- 用户可能误以为元宝能读取私人聊天；产品必须清晰说明边界。
- 社交关系和聊天属于高敏感数据，不应自动沉淀为长期 Agent memory。
- 公开官方 memory 文档不足，当前不宜高估长期记忆成熟度。
