# 字节跳动：豆包 / 抖音

## 产品机制

### 豆包已公开

- 豆包可从用户与豆包的对话文本（含语音转写）抽取并总结有用细节，作为后续回复背景；不包括用户上传的图片、文件、链接和视频通话画面。
- 用户可在设置中启停、查看和删除单条/全部记忆，也可在对话中要求忘记。
- 关闭 memory 后不再读取或更新，但不会自动删除已有 memory；重新开启后未删除内容会再次被参考。
- 删除聊天记录不等于删除已抽取 memory；删除 memory 的生效存在处理时间。
- 豆包还把输入、点击、搜索、浏览、分享和反馈用于个性化内容推荐；该开关与 memory 控制是不同机制。

### 抖音

- 抖音拥有成熟兴趣图谱、短视频多模态理解和实时推荐信号。
- 公开证据不足以证明豆包会默认读取用户抖音兴趣画像；豆包隐私政策明确描述某些跨产品信息需具体授权，不能把集团数据互通视为默认事实。

## Memory 分层映射

| 层级 | 产品机制 | 证据 |
|---|---|---|
| 短期 | 当前对话、语音转写上下文 | 已上线 |
| 中期 | 历史对话、近期搜索/点击/反馈、授权合作方信息 | 已上线但用途分属 memory / 推荐 |
| 长期 | 对话中抽取的有用细节与用户主动要求记住的信息 | 已上线 |

## Agentic Search 注入点

- Memory 作为生成背景，减少重复输入。
- 个性化推荐信号可用于 bots、输入建议和内容候选。
- 若与抖音搜索/电商连接，记忆可影响视频、商品与本地生活排序，但实际跨产品路径需明确授权和实测。

## 技术判断

- 官方 FAQ 明确了文本抽取、控制与删除语义，但未公开 memory schema、retrieval 或 ranking。
- 产品上应区分三套平面：对话 memory、豆包内个性化推荐、跨应用授权数据。

## 风险与开放问题

- 关闭不等于删除，用户容易误解。
- 删除异步生效，需要明确 SLA 和缓存传播。
- 抖音兴趣画像若进入 Agent，必须避免将娱乐点击直接当成购买或长期偏好。
