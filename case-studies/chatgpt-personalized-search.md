# Case Study：ChatGPT 风格的个性化 Agentic Search

> 本页给出产品与技术参考架构；具体已上线能力以 [OpenAI 公司页](../companies/overseas/openai.md) 和官方来源为准。

## 场景

用户问：「帮我找国庆去东京、适合带父母的酒店。」

可用上下文：

- 短期：本轮预算、日期、房间数
- 中期：正在规划的东京行程，已排除新宿夜生活区
- 长期：用户明确保存「偏好安静、近公共交通」；过去曾带父母旅行

## Agent 执行路径

1. Intent router 判断这是高个性化价值的旅行决策。
2. 读取当前会话和东京项目；长期只读取 travel scope。
3. 将预算、日期作为 hard filter；安静、近地铁作为 soft ranking signal。
4. 并行搜索酒店库存、地图交通、评论与官方信息。
5. 通用召回后做个性化 rerank，保留一个非典型但高质量探索候选。
6. 生成三档方案，并分开说明：
   - 本次明确要求
   - 之前保存的偏好
   - 实时价格与评论证据
7. 用户选定后，写入东京项目，不自动晋升新的长期偏好。
8. 若用户要求持续盯价，创建有明确授权、截止日期和通知频率的中期 tracker。

## 推荐输出

```text
我优先按你这次的预算，以及之前保存的「安静、近公共交通」
做了排序。以下价格和空房来自今天的实时结果：

1. A：约束满足最好……
2. B：交通最好，但房间较小……
3. C：探索选项，稍远但环境更安静……

[查看本次使用的偏好] [不使用个性化重新排序]
```

## Why this is agentic

它不只是生成答案，而是：

- 跨来源检索与验证
- 在多步计划中持续维护约束
- 用 memory 改写和重排，而非简单附加背景
- 可调用地图、库存、预订和通知工具
- 将任务结果和长期用户模型分开写回

## 核心失败案例

- 将「这次带父母」错误保存为所有旅行的永久偏好
- 因历史预算而过滤掉用户本次明确想看的高端酒店
- 只返回与过去相似的区域，失去探索性
- 解释中泄露用户未期望提及的历史行为
- 用户删除偏好后，派生项目摘要仍继续使用
